# Knight Tour Puzzle

スマートフォン向け、全5問のナイトツアーパズル。外部ライブラリ・ビルド不要の静的HTML / CSS / JavaScriptです。`index.html` を開けば遊べます。

## 遊び方と保存

緑のマスへナイトを動かし、各マスを1回だけ通ります。「1手戻る」「最初から」は全問で使えます。行き止まりでも何度でも戻れます。第5問だけは最後の位置からスタートに1手で戻れることも必要です。条件を満たす最終マスに着いた時点でクリアになり、実際にスタートを再訪問する操作は不要です。

クリアすると第1〜4問には「次の問題へ」が現れます。画面下部の問題選択から全問へ移動でき、「前の問題へ」も使えます。クリア済みにはチェックが付きます。

問題番号・問題ごとの途中の経路・クリア済みの記録を、操作ごとにlocalStorageへ保存します。クリア後にやり直してもクリア済みの印は残ります。保存データの経路は読み込み時に検証します。保存が使えない環境でもプレイでき、その場合は画面に保存不可を表示します。進捗は同じブラウザー・同じ公開元に保存され、別端末や `file://` から公開URLへは引き継がれません。継続利用はGitHub PagesなどのHTTP(S)公開元を推奨します。

## 採用した5問

座標は盤面を囲む長方形の左上を **1行1列** とします。空白も座標上は数えます。

| 問題 | サイズ・形 | 使用マス数 | スタート | クリア条件 | 確認した解数 |
|---|---|---:|---|---|---:|
| 01 はじめの一歩 | 3行×4列、長方形（既存のまま） | 12 | 1行1列 | 全マスを1回ずつ通る | 2 |
| 02 小さな寄り道 | 4行×4列から上の両隅（1行1列・1行4列）を除く | 14 | 2行2列 | 全使用マスを1回ずつ通る | 12 |
| 03 先を見ながら | 5行×4列から上2行の両端（1行1列・1行4列・2行1列・2行4列）を除く | 16 | 1行2列 | 全使用マスを1回ずつ通る | 19 |
| 04 道をつなごう | 5行×4列から上の両隅（1行1列・1行4列）を除く | 18 | 2行1列 | 全使用マスを1回ずつ通る | 58 |
| 05 はじまりのそばへ | 第4問と同じ | 18 | 2行1列 | 全使用マスを1回ずつ通り、最後からスタートへ1手で戻れる | 8 |

解数は固定スタートからの訪問順を数えたものです。第5問は逆向きの経路も別々に数えています。採用した全問で探索を最後まで実行しました。第5問では全18マスを通る58経路のうち8経路が追加条件も満たします。

## 選定調査と難易度

`scripts/explore.cjs` で、サイズ・形・スタート・クリア条件を組み合わせた42候補を調査しました。3×4、3×5、4×4の角を除く形、5×4の複数形状、5×5、5×5中央抜き、6×5を含みます。候補ごとの記録は `tests/candidate-results.json`、採用した問題の再検証結果は `tests/selected-results.json` にあります。

- 解がない候補を除外しました。たとえば、調べた3×5のスタートでは解がなく、5×5中央抜きでは全マスを通れる候補でも第5問の条件を満たせませんでした。
- 6×5は候補ごと300万探索状態の上限を設けたため、記録の `exhaustive: false` は部分探索です。その解数・成功率は探索済み分の下限であり、0でも解がないとは断定しません。大きさと分岐量から今回は不採用です。
- 全4隅を除く5×4は16マスでも無作為選択時の成功率が16〜24%と高く、第3問としては第2問より易しくなる可能性があるため不採用にしました。
- 横幅は全問4列に統一しました。複雑な穴を作らず、上部だけを絞る輪郭にすることで、マスを小さくせず盤面を見渡せます。

比較指標は以下のとおりです。無作為選択の成功率は、毎手その時点の合法手を等確率で選び、戻らず進んだ場合の確率を全探索で計算したものです。「先を考慮」は、すぐ行き止まりになる手を避け、移動後の行き先が少ないマスを優先し、同数なら等確率で選ぶ方式です。人間の実測成功率や解答時間ではありません。

| 問題 | 途中の最大選択肢 | 行き止まり経路数 | 行き止まり時の平均訪問数 | 無作為選択の成功率 | 先を考慮した成功率 |
|---|---:|---:|---:|---:|---:|
| 01 | 2 | 13 | 8.92 / 12 | 25.00% | 100.00% |
| 02 | 3 | 188 | 11.11 / 14 | 12.50% | 100.00% |
| 03 | 3 | 714 | 12.46 / 16 | 5.73% | 83.33% |
| 04 | 4 | 5,292 | 13.69 / 18 | 1.99% | 77.78% |
| 05 | 4 | 5,342 | 13.73 / 18 | 0.26% | 16.67% |

第5問の行き止まりには「全マスを通ったがスタートへ戻れない」50経路も含めています。

第2問は選択肢を少し増やしつつ、先を見れば短い経路を組み立てやすい設定です。第3問は序盤の選択で後に行き詰まる経路があり、3手進んだ時点でまだ移動可能でも、そこからはクリア不能な経路の存在を検証しています。第4問は選択肢を増やす一方、先の移動先を考慮すると成功率が約78%になり、試し続けるだけでなく考えて解ける余地を残しました。第5問は慣れた第4問の形を使い、最後の位置まで計画する条件だけを追加しています。

これらに基づく難易度順は設計上の見込みです。人によるプレイテストは未実施です。画面内に解答経路や理論の解説は表示しません。

## GitHub Pages

Settings → Pages → Deploy from a branch で、公開するブランチと `/ (root)` を選択します。ファイル参照は相対パスなので、リポジトリ名を含むURLで動きます。公開前のローカル確認では任意の静的HTTPサーバーも使えます。

## 自動検証

Node.jsで次を実行します。通常のアプリ利用にはNode.jsは不要です。

```sh
node scripts/explore.cjs
node tests/verify.cjs
```

探索実装はアプリの移動判定に依存せず、独立した座標判定で解を求めます。各問で少なくとも1つの完全な経路を実際のゲーム処理に入力してクリアを検査し、全到達経路について解数・行き止まり数・戻る操作も照合します。再訪問、不正な移動、欠けたマス、クリア前の誤判定、リセット、保存された経路の復元、第5問の戻れない完全経路も検証します。

ブラウザー検証は開発時のみPlaywrightとChrome/Chromiumを使います（配信するアプリには読み込みません）。利用可能な環境で:

```sh
node tests/browser.cjs
```

既存Chromeを使う場合は `BROWSER_EXECUTABLE_PATH` に実行ファイルのパスを指定できます。Playwrightが環境側に配置されている場合は `NODE_PATH` でパッケージの場所を指定できます。

実施済みのブラウザー検証:

- 全5問を完全な解答経路でタップ操作し、クリアを確認。
- 全問の行き止まり、戻る、リセット、クリア後の戻るを確認。
- 第5問で全マス到達だけではクリアしないこと、読み込み直してもその状態が復元されることを確認。
- 次へ・前へ・問題選択、クリア済みの印、全問クリア表示を確認。
- ブラウザーを完全に閉じ、同じ保存プロファイルで再起動して問題番号・途中経路・全クリア記録を復元。
- 壊れた保存内容、無効な経路、保存無効の環境でもプレイ可能であることを確認。
- 幅320 / 390 / 768 / 1440pxで横はみ出しがなく、全問の各マスが44px以上であることを確認。
- 第1問の盤面の座標・幅・高さが、上記4画面幅で変更前と完全一致。
- キーボード操作、公開サブパス相当のURL、JavaScriptエラーがないことを確認。

## ファイル

- `index.html` / `style.css`: 既存画面と、問題選択・第5問の説明・次へボタン。
- `game.js`: 5問の定義、移動とクリアの判定、経路の復元。
- `app.js`: 盤面表示、操作、問題切り替え、進捗反映。
- `storage.js`: localStorageの読み書きとエラー処理。
- `scripts/explore.cjs`: 候補の探索と比較指標の算出。
- `tests/verify.cjs`: 全5問の独立探索・ルールと保存の検証。
- `tests/browser.cjs`: ブラウザー上での操作・保存・表示検証。
- `tests/candidate-results.json` / `tests/selected-results.json`: 再現可能な探索結果と検証用の経路。
